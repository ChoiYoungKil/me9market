Me9 소셜로그인 작업 및 검증 상태
검증일: 2026-10-16 KST

요청 해석
전달된 네이버·구글 개발자 계정의 기존 애플리케이션에서 OAuth 정보를 확인하거나 생성하고,
기존 Me9 로그인 화면에서 실제 소셜 인증 및 Me9 세션 로그인이 되게 하는 작업이다.
메일은 개발자 계정 안내이며 별도 기능 명세나 신규 사용자 계정 생성 요청으로 취급하지 않았다.
계정 비밀번호·OAuth Secret·인증 토큰은 이 보고서나 Git에 저장하지 않는다.

구현한 코드
- Google Authorization Code + PKCE, Naver Authorization Code 인증 연결
- 세션에 묶인 일회용 state, 10분 만료, 인증 거절·실패 안내
- 소셜 서비스의 고유 ID와 Me9 회원을 별도 테이블로 연결, 토큰 저장 안 함
- 신규 가입 시 기존 필수 약관 3개 검증 및 동의 증거 저장
- 이메일이 같다는 이유로 기존 회원에 자동 연결하지 않음
- 기존 로그인 + 최근 비밀번호 확인 후 소셜 계정 연결·해제
- 비활성 회원 로그인 차단, 다른 회원 소셜 계정 연결 차단
- Shop 로그인에서 시작한 경우 유효한 채널 접근을 유지하고 원래 채널로 복귀
- 인증 설정이 없거나 콜백 주소가 사이트와 맞지 않으면 버튼 노출·인증 시작 차단
- 운영환경 콜백 HTTPS 필수
- 로컬 개발 DB에 social_accounts 신규 테이블만 추가 (운영 DB 변경 없음)

추가 링크/화면 수정
- 마이페이지 상품 링크·QR이 채널 입장 이후 해당 상품으로 이동
- 비공개 채널은 인증을 유지하고 상품 목적지를 보존; 타 채널 상품이나 중단 상품 차단
- 포인트·쿠폰 실제 페이지네이션, 다른 회원에 배정된 쿠폰 조회 제한
- 관리자 설정 및 마이페이지·채널 메뉴 링크 수정
- 소셜 가입 모바일 제목이 고정 헤더에 가려지는 문제 수정
- 배포 점검에 공통 스타일·스크립트, Vite 참조 파일, 배송비·소셜 연결 스키마,
  활성 소셜 제공자의 OAuth 설정 검증 추가

실제 콘솔 연결 및 인증 검증 결과
- 사용자 로그인 후 Chrome 영길 프로필에서 두 개발자 콘솔에 정상 접근했다.
- 네이버 기존 앱 ‘미구마켓’을 확인했다. 개발 중 상태이며 이름·이메일 제공이 설정돼 있다.
- 기존 서비스 URL은 http://replyer.co.kr, 콜백도 http://replyer.co.kr였다.
- 사용자 명시적 승인 후 서비스 URL을 https://front.replyer.co.kr로 변경했다.
- 네이버 콜백은 아래 2개로 저장 후 새로고침해 영속 저장을 확인했다.
  https://front.replyer.co.kr/auth/social/naver/callback
  http://127.0.0.1:8000/auth/social/naver/callback
- 네이버 기존 Client ID/Secret을 비공개 로컬 .env에 연결했다. Secret 재발급 없음.
- 처음 읽은 Secret은 브라우저가 마스킹한 표시값이었다. 콘솔의 ‘보기’ 기능으로 실제
  Secret을 확인해 교체했으며, 마스킹값을 정상 설정으로 처리하지 않도록 검사도 추가했다.
- 구글 계정 skytech3833@gmail.com의 M9MARKET001 프로젝트에는 초기 OAuth 구성이 없었다.
- 사용자 명시적 승인 후 Me9 Market, 외부 사용자 유형, 테스트 모드로 초기 설정했다.
  Google API 서비스 사용자 데이터 정책 동의도 사용자 승인 후 진행했다.
- 웹 OAuth 클라이언트 ‘Me9 Market Web’을 생성하고 아래 콜백을 등록했다.
  https://front.replyer.co.kr/auth/social/google/callback
  http://127.0.0.1:8000/auth/social/google/callback
- 구글 Client ID/Secret을 비공개 로컬 .env에 연결했다. Secret은 출력·Git 저장하지 않았다.
- 구글 개발 계정 자체를 테스트 사용자 1명으로 등록하고 저장된 목록에서 확인했다.
- 로컬에서 두 제공자의 enabled/키/콜백 설정 검사가 통과했다.
- 실제 Google 인증: Me9 로그인 버튼 → 계정 선택 → 기본 프로필 제공 동의 → 실제
  토큰 교환 및 프로필 수신 → Me9 소셜 가입 → 마이페이지 로그인까지 확인했다.
  사용자가 로컬 가입 화면의 동의를 제출했고, DB에서 Google SocialAccount 연결·활성
  회원·필수 동의 기록이 존재함을 확인했다. 회원정보에서도 ‘Google 연결됨’이 표시됐다.
- Google 회원으로 Me9 로그아웃 후 다시 Google 로그인 버튼·동일 계정 선택을 거쳐
  추가 가입 없이 기존 회원의 마이페이지로 돌아온 것을 확인했다.
- Google/Naver 재로그인 후 각각 연결 레코드가 1개로 유지돼 중복 연결이 생기지 않았다.
- 실제 Google 검증 자료는 Git 외부 비공개 경로에 보관했다.
  /private/tmp/me9-google-first-login-success.jpg
  /private/tmp/me9-google-connected-profile.jpg
  /private/tmp/me9-google-relogin-success.jpg
- 연결·해제의 비밀번호 확인, 타인 계정 연결 차단, 동일 이메일 자동 연결 금지,
  취소·만료·재전송·비활성 회원·Shop 복귀 등은 자동 회귀 테스트로 검증했다.
  실제 제공자의 계정 연결·해제까지 모두 실검증했다는 의미는 아니다.
- 실제 Naver 인증: 단체 계정으로는 제공자가 인증을 거부한다는 안내를 확인했다.
  사용자에게 개인 계정을 확인받아 테스터 1명을 등록했고, 새로고침 후 목록 유지도 확인했다.
  개인 계정으로 실제 인증·가입을 마친 뒤 Me9 마이페이지에 로그인된 상태를 확인했다.
- 로컬 DB 읽기 검증에서 Naver SocialAccount 연결, 활성 회원, 필수 약관 동의 기록이
  모두 존재함을 확인했다. 회원정보 화면에서도 ‘네이버 연결됨’이 표시됐다.
- Me9에서 로그아웃한 뒤 네이버 로그인 버튼으로 다시 인증했고, 추가 가입 없이
  기존 회원의 마이페이지로 돌아가 로그인된 상태가 유지되는 것을 확인했다.
- 실제 Naver 검증 자료는 Git 외부 비공개 경로에 보관했다.
  /private/tmp/me9-naver-first-login-success.jpg
  /private/tmp/me9-naver-connected-profile.jpg
  /private/tmp/me9-naver-relogin-success.jpg
- 테스트 전용 환경에서는 실제 OAuth 설정을 강제로 비활성화하고 비밀정보를 비워,
  개발자 콘솔에서 받은 실키가 자동 테스트에 섞이지 않게 분리했다.

운영 공개 전 추가 확인
- 네이버는 개발 중 상태이며 일반 고객 이용을 위한 검수 승인 전이다.
- 네이버 검수 페이지 진입 시 애플리케이션 로고 등록이 먼저 필요하다는 안내를 확인했다.
  로고 업로드·검수 신청은 아직 하지 않았다.
- 구글은 테스트 모드이며, 콘솔에서 브랜딩 구성을 완료해야 앱 게시가 가능하다고 안내한다.
- 운영 약관 URL/문서 버전, 운영 HTTPS, 실제 PG 등 기존 배포 요건도 여전히 별도 검증이 필요하다.
- 운영 서버의 환경설정 변경이나 운영 배포는 하지 않았다.

운영 HTTPS 재검증
https://front.replyer.co.kr/: curl 7, port 443 연결 실패
https://admin.replyer.co.kr/admin/login: curl 7, port 443 연결 실패
운영 콜백과 로그인 세션 검증에는 정상 HTTPS가 필요하다.
운영 배포 없음. 전체 운영 준비 완료 또는 실서비스 소셜로그인 완료로 판정하지 않는다.

개인 테스터 등록 완료
사용자에게서 개인 네이버 아이디를 확인한 뒤, 기존 미구마켓 앱의 테스터로 1명을 추가했다.
새로고침한 서버 목록에서도 해당 테스터가 유지됨을 확인했다. 관리자 권한은 추가하지 않았다.
검증 화면은 Git 외부 비공개 자료 /private/tmp/me9-naver-tester-0kil1-saved.jpg 에 보관했다.

최종 판정
네이버·구글 모두 로컬 개발 환경에서 신규 소셜 가입, 로그인, 로그아웃 후 재로그인이
실제로 동작한다. 테스트 계정 2개의 연결·활성 상태·동의 기록을 로컬 DB에서 확인했다.
로컬 가입 검증은 운영 동의 문서의 승인·공개 검수와 별개다.
운영 사용자 공개와 전체 쇼핑몰 운영 배포는 위 미완료 요건 때문에 수행하지 않았다.
