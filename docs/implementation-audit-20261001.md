# 기획 대비 구현 점검 및 수정 내역

최종 갱신: 2026-10-03 KST. 현재 수정분의 두 서버 반영과 요청 명령 실행, 실제 계정 4종 Chrome 검수 결과는 [운영 배포 기록](../DEPLOYMENT_REPORT_20261003.md) 참조. 최신 전체 회귀 테스트는 231개/2,829개 검증 항목이다. 아래 기록은 당시 상태를 보존한 이력이며 전체 요구 인수 완료를 의미하지 않는다.

## 최신 판정

**PG/SMS/소셜을 제외해도 전체 구현 및 전수 인수 완료는 아니다.** 이후 사용자가 현재까지 수정분을 우선 Git에 올리고 두 서버에 적용하도록 명시적으로 요청했다. 이 최신 승인에 따라 백업 후 제한 배포와 실제 브라우저 검수를 진행한다. 아래 읽기 전용 서버 점검 및 미배포 기록은 해당 승인 이전의 이력이다. 실제 실행 결과는 별도 배포 기록으로 구분한다.

### 추가 수정 및 재검증

- 금액 옵션: 별도 증감액 필드, +/- 가격 계산, 주문 스냅샷, 검증 오류 시 상품/옵션 롤백, 옵션 누락 색상 처리. 주문 재고에 연결된 옵션은 삭제 차단. 가격이 달라지는 교환은 차액 PG 미연동으로 차단.
- 클레임: 취소 요청 전 상태 보존/거절 복원, 원문 회수/승인/보류/완료 단계 제한, 보류 해제, UI/서버 공통 상태표, 단계 건너뛰기와 중복 확정 차단.
- 모니터링 관리자: `/shop-monitor/login` 전용 인증, 해당 Shop/판매자의 주문 조회만 제공, 사용기간/중지/비밀번호 변경 시 세션 무효화, 고객 개인정보 및 다른 Shop 데이터 미노출.
- 후기: 0.5점 저장/검증/hover/터치/키보드/선택해제. 기본 5점 자동 제출 제거. 구매확정 이력 없는 후기와 범위 밖 점수 차단.
- 인보이스: 다른 판매자의 HTML/PDF 조회 차단, 비회원 주문 오류 수정, 원화/실 배송비/포인트/쿠폰 표시, 한글 PDF, HTML 이스케이프 및 PDF 원격 리소스 비활성화. 고객 다운로드와 관리자 범위 조회를 분리.
- 화면 연결: 빈 홈페이지를 입장코드/조회/관리자/공지로 연결, 가짜 업체 정보를 승인 설정값으로 대체, 관리자 죽은 링크 정리, 취소/환불 정책 조회 추가, 주문 목록 고정 0 금액을 정산 계산 기반 예상값으로 대체, 옵션 팝업 문자열 이스케이프.
- 보안: Shop 모델 직렬화에서 비밀번호/PG 키 숨김. 부운영자 5종 권한의 32개 조합에 대해 메뉴 그룹 5개와 소유자 전용 경로 접근 검증.

### 확인 결과

- 독립 테스트 DB 전체 테스트 **230개 통과 / 2,819개 검증 항목**.
- Shop 신규 디자인 **54개 화면 조합**(18개 x 1440/768/390px), 홈페이지/모니터링 9개, 인보이스 3개, 관리자 대시보드 3개 검사. JS 오류/자산 누락/가로 넘침 0. 관리자 차트 픽셀과 한글 PDF 1페이지 시각 확인. 모든 관리자 화면 반응형 합격을 뜻하지 않는다.
- 변경 PHP 60개 및 JS 4개 문법 검사 통과. Blade 캐시, 공백 검사, Composer 설정/플랫폼 검사, Composer 운영 의존성 및 npm 운영 의존성 보안 검사 통과.
- 격리된 운영 설정/라우트 캐시 및 `deployment:check --restricted` 통과. 운영 모의결제 및 테스트베드 비활성화 상태의 라우트 363개 검사. 실제 서버 실행 결과가 아니라 로컬 배포 리허설이다.
- 새 `2026_10_02_000004` 마이그레이션은 로컬 개발 DB에만 적용. 운영 주문/원장/정산 값은 변경하지 않았다.

### 배포 차단 사항

1. 기획 배송비 RF-02-12의 변동/구간별 금액·수량, 2/3권역 배송비/지역 제한 및 주문 주소 연계가 미구현이다. 기본 상품별 무료/유료/조건부/착불만 검사 통과했다. 이를 외부 연동 제외로 분류하지 않는다.
2. 최종 승인 이용약관/개인정보/제3자 동의, 시행 버전, 실제 사업자 표시 정보와 과거 계약/정산 근거가 없다. 소프트웨어 동의 기록 기능은 있지만 문서 적용/과거 자료 대조 완료는 아니다.
3. 두 운영 도메인의 HTTPS 443 연결 실패, 서버 443 리스너 없음. APP_URL은 HTTP, Secure 쿠키 false. admin 서버는 storyboard 설정 true. admin 계정은 sudo 권한이 없다. TLS/웹 서버 변경 가능한 인프라 담당자의 조치가 필요하다.
4. 기존 원문 요구의 다수 세부 입력/화면/예외 조합, 부하/동시성 실측, 백업 복구 및 운영 메일 도달은 미검수다. 전체 요구를 단위 테스트 수로 대체하지 않는다.

SSH 재점검에서 각 DB 조회는 주문 2건/정산 실행 0건이며 DB 호스트/DB명 해시가 같았다. admin에만 스케줄러/큐 cron이 등록되어 있었고 front crontab은 없었다. 두 저장소의 기존 미커밋 storyboard 파일/중첩 디렉터리와 서버 고유 커밋은 그대로 보존했다. 이번 점검 중 생성된 194바이트 git 로그 임시 파일은 내용 확인 후 제거했다. 서비스/DB/배포 상태는 바꾸지 않았다.

항목별 CSV는 변경 내용을 반영했다. 미완료·부분검증·미검수 구분은 유지한다. 원문 271개 슬라이드, 231개 화면 슬라이드/229개 고유 RF, 요청서 45건, 참고 문서 988개 행을 집계한다.

로컬 실행 중인 검수 주소: `http://127.0.0.1:8001/admin/storyboard-test`(전체관리자 로그인 필요). 해당 서버 프로세스에만 테스트베드를 활성화했다. 저장소 기본값과 운영용 리허설에서는 비활성이다.

## 2026-10-02 초기 검수 기록

**전체 요구사항 완료/운영 인수 완료가 아니다.** 사용자가 `자료 확인 후 전체 배포`를 선택했으므로 Git 푸시, 운영 `git pull`, 운영 마이그레이션/캐시 변경은 보류했다. 소셜/PG/SMS 외에도 아래 구현 차이 및 미검수 항목이 남아 있다. 로컬 테스트 합격을 운영 무장애 보증으로 해석하지 않는다.

### 요구사항 대조표

- [271개 슬라이드 검수표](requirements-audit-20261002.csv): 화면명, 원문 Description, 현재 판정, 관련 코드/테스트, 남은 검수 기록.
- [작업요청서 45건 대조표](requested-pages-audit-20261002.csv): 범위 요청은 개별 RF/슬라이드로 연결.
- [기타 문서 988개 행 인덱스](supporting-documents-index-20261002.csv): 7개 XLSX의 FileMap/요청서/WBS/산출예시 등을 원문 행 단위로 연결. 계정 이력 시트 제외. 원문 진행상태를 현재 합격 판정으로 사용하지 않는다.
- 화면 메타데이터 기준 231개 슬라이드에 229개 고유 RF가 있다. 나머지 40개는 표지/개정/구분 페이지다. 기존 227개 집계는 슬라이드 86/90의 OG 필드명 `Description`을 화면 설명 시작으로 오인해 두 화면을 누락한 결과이며 이번에 보정했다.
- 표의 관련 테스트는 해당 기능 일부의 근거다. **모든 하위 요구의 개별 증명은 아니며**, 부분검증/미검수 항목을 합격으로 올리지 않았다. 동일 RF의 구 설계(188)는 후속 설계(189)로 구분했다.

### 검증 결과

- 전체 자동 테스트: **215개 통과 / 1,365개 검증 항목** (`newme9markte_testing` 전용 DB).
- Shop 신규 디자인 18개 × 3개 폭 = **54개 화면 검사 통과**. 포인트 입력 합계, 주문자/배송지, 옵션, 팝업 포함. JS 오류/자산 누락/가로 넘침 0.
- 어드민 대시보드 3개 폭 검사 통과. 차트 2개의 실제 픽셀과 데이터 확인. 모든 관리자 화면의 반응형 합격을 의미하지 않는다.
- 로컬 `view:cache`, Git 공백 검사, 임시 운영 캐시 `config:cache`/`route:cache`/`deployment:check --restricted` 통과. 캐시 라우트 358개에 개발/스토리보드 경로 없음. 제한 배포를 실행하거나 승인한 것이 아니라 로컬 재현 검사다.
- 로컬 개발 DB(127.0.0.1)에 신규 마이그레이션 3개 적용. 운영 DB에는 적용하지 않음.
- 로컬 기존 주문 감사는 종료 코드 1: 과거 주문 1건의 결제 스냅샷, 품목 2건의 정산 정책 스냅샷 누락. 누락을 현재 설정으로 메우지 않음.
- 실제 외부 송신/PG 환불, 부하 및 다중 연결 동시성 실측, 모든 역할×메뉴×예외 조합은 미완료.

## 운영 안전성 추가 검수

사용자의 운영 안정성 요구에 따라 성공 경로 외의 실패/재시도 경로를 추가 검수했다. 아래 문제는 수정 전 회귀 테스트 실패로 재현하고 수정 후 통과를 확인했다.

- 옵션 변경 후 이전 옵션 재추가 시 장바구니 키가 충돌해 다른 옵션/수량을 덮어쓰던 문제 수정.
- 문자 로그 드라이버를 실제 발송 성공으로 기록하고 과금하던 문제 수정. `simulated` 상태, 발송 시각 없음, 과금 0으로 저장한다. 실제 발송 실패도 과금하지 않는다.
- 문자 기록 장애로 이미 접수된 취소 요청에 500 응답이 반환되던 문제 수정. 업무 처리 결과는 유지하고 애플리케이션 오류 로그에 주문 식별자를 남긴다.
- 문자 요금 누적은 과거 모델 객체의 값으로 덮어쓰지 않고 DB 원자적 증가로 처리한다. 발송 기록 갱신과 요금 반영은 같은 트랜잭션에 포함한다.
- `staging` 등 `production` 이외 환경에서 모의 결제가 허용되던 조건을 `local/testing` 허용 목록으로 변경.
- 새 인증번호 사용 뒤 예전 미사용 번호가 다시 유효해지던 문제 수정. 가장 최근 번호만 검사하며 사용 완료 번호는 거절한다.
